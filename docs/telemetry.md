# Отчёты и обновления Kawa VPN

В настройках доступны «Сообщить о проблеме», автоматические отчёты и проверка обновлений.

Отчёт включает версию приложения, ОС/архитектуру, модель устройства, CPU/RAM, тип подключения, очищенные последние логи и IP, который видит сервер при отправке. При активном VPN это обычно IP выхода VPN, а не исходный IP абонента. IP определяется сервером, не из присланного поля. IP не собирается из сторонних сервисов.

Автоматическая отправка требует согласия пользователя на этот состав данных. Старое согласие без IP не переносится автоматически: приложение спрашивает снова. Ручной отчёт показывает состав данных и отправляется по явному нажатию; доступны предварительный просмотр и код KW-. Ссылки подписок, пароли, токены и ключи вырезаются из текстов. Дампы памяти не отправляются.

Rust panic сохраняет backtrace; фатальная ошибка Windows сохраняет код исключения и последний снимок логов. Аварийный выход без кода отмечается отдельно как «сбой или принудительное завершение» — это может быть закрытие через диспетчер задач. Снимок обновляется в фоне каждые 10 секунд; последние секунды перед тяжёлым сбоем могут отсутствовать. При следующем запуске отчёт восстанавливается в очереди. Штатное закрытие удаляет маркер сеанса.

Отчёты сохраняются атомарно, отправляются после восстановления сети, имеют устойчивый код для защиты от повторной регистрации. Отказ от автоматических отчётов отключает сбор и удаляет очередь. Сервер повторяет доставку уведомлений при сбое Telegram. Администратор получает описание и JSON с логами через главного бота. При неопределённом сетевом исходе запроса Telegram возможно повторное уведомление с тем же кодом.

Сервер: Германия, HTTPS https://hub.example.com/kawa-app.
Служба: kawa-hub. Состояние: /var/lib/kawa-hub, только локальный сервис и администратор имеют доступ. Срок хранения отчётов: 90 дней. Публичных маршрутов чтения отчётов нет.

Приложение проверяет обновления через 30 секунд после запуска и затем раз в 6 часов. Новая версия автоматически скачивается в фоне; полоса обновления появляется в приложении. Установка запускается кнопкой «Установить», после подтверждения Windows. Перед установкой VPN отключается штатно. Вход и пользовательские настройки остаются в профиле пользователя.

Манифест подписан отдельным ключом Kawa Ed25519. Подпись привязана к SHA-256 манифеста, что позволяет безопасно получать её во время публикации нового выпуска. Установщик проверяется по размеру и SHA-256. Закрытый ключ остаётся на машине выпуска, не на Германии и не в архиве исходников. Первая версия с этим механизмом — 0.4.9; более старые клиенты обновляются вручную.

Публикация следующего выпуска:

```powershell
./packaging/publish-kawa.ps1 -Version 0.4.10 -Installer ./KawaVPN-Setup-0.4.10-x64.exe -SigningKey /path/to/private/kawa-update-signing.pem -SshKey /path/to/ssh/key -KnownHosts /path/to/known_hosts -Notes "Описание обновления"
```

Python для публикации требует cryptography и paramiko. Поднять версии пакетов, собрать и проверить установщик до публикации. Скрипт сверяет закрытый ключ с публичным ключом в исходниках клиента, проверяет загруженный файл, сохраняет предыдущий манифест и не позволяет заменить опубликованный номер версии другими байтами. Бинарник загружается первым, активный манифест переключается последним. Не менять публичный ключ при обычных выпусках. Закрытый ключ и SSH-ключ нельзя добавлять в репозиторий или распространяемые архивы.
